# Evolution HQ — the permanent-progression headquarters

The **Evolution** tab is the home of everything permanent: Genome Core upgrades (per-run currency)
and the Ascendant Tree (prestige). This redesign turns the old two-panel shop into a **sectioned
headquarters** with a live statistics readout and a subtle biological backdrop.

Scope: presentation + a pure read-model. It reads the existing `meta` selectors (Part F data) and
routes purchases through the existing `meta.buyUpgrade` / Ascendant / Molt APIs. **No balance, save,
or sim changes** — so it's golden/save-safe by construction.

## Layout (top → bottom)

1. **Header + animated backdrop.** A title band over a CSS-only living background: drifting "cells"
   and a rotating DNA double-helix. Pure decoration (`aria-hidden`, honors reduced-motion).
2. **Statistics panel** — the account at a glance, 9 stats:
   Total Power · Permanent Damage · Permanent Biomass · Permanent Hero Strength · Tower Capacity ·
   Prestige Multiplier · Lifetime Genome Cores · Lifetime Ascendant Cells · Campaign Completion.
3. **Genome Core sections** — one card grid per `GenomeCategory` (Combat, Economy, Hero, Tower,
   Infrastructure, Utility). Each section header shows: icon · name · one-line description ·
   a progress bar (levels bought / total) · completion % · Genome Cores spent.
4. **Ascension** — the Molt gate + Ascendant Tree (the existing `PrestigePanel`, reused as-is under
   an HQ section header, so there's one source of truth for prestige).
5. **Future Locked** — a teaser section naming deferred systems (Speciation, Transcendence), so the
   long horizon is visible. Non-interactive.

## Upgrade card

Each Genome upgrade renders a card with: current level · max level · a segmented progress bar ·
current effect → next effect · Power Score gain preview (`meta.previewPower`) · cost (or MAX) ·
buy button. States: **buyable** (affordable), **unaffordable** (dimmed cost), **completed** (maxed,
check + muted), **hover** (lift + rarity-less accent glow). Buying triggers a brief pulse
(`is-just-bought`) — animated purchase feedback.

## Read-model — `state/evolutionHQ.ts` (pure)

`evolutionHQView(save)` → `{ stats: StatLine[]; sections: GenomeSection[] }` where a
`GenomeSection` bundles `{ category, icon, title, desc, cards, boughtLevels, totalLevels,
completionPct, coresSpent }` and a `GenomeCardView` carries the per-card fields above (effect
strings via a field→unit formatter: multiplier fields render `±X%`, flat fields render `+N`).
Pure over `SaveData` + the config, so it's unit-testable and adding an upgrade/category needs
nothing here. Power previews stay in the component (they call the reactive store).

## Scale / future-proofing

Sections are generated by grouping `META_UPGRADES` on `category`, so 50+ genome upgrades and new
categories render with zero component changes. The Future-Locked section is data (a small array),
ready to promote to a real tree when its systems ship.

## §runaway (2026-07) — the uncapped Genome Core sink + HQ overhaul

Every category now fields exactly **one RUNAWAY mutation** — an *uncapped, endlessly
upgradeable* upgrade (`UpgradeDef.infinite: true`, `maxLevel: Infinity`), the deliberate
**late-game Genome Core sink**:

- **Diminishing returns, never zero.** The cumulative effect folds at **√level**
  (`upgradeEffectUnits` in `core/config` — the ONE place the curve lives; both seams,
  the labels, and Power previews all route through it). Each level adds less than the
  last, but always more than nothing — so every buy still nudges the Power Score
  (pinned by `meta.test` + the powerIntegration sweep).
- **Ever-increasing cost.** The standard geometric curve with a compounding
  `costMult ≥ 1.1` (validator-enforced for infinite defs): base 160–220 cores at
  ×1.15–1.16 per level. By level ~30 a single level costs more than most capped
  trees in full — sink territory.
- **The six**: Runaway Lethality (Combat, +2%×√n tower damage) · Runaway Metabolism
  (Economy, +2%×√n biomass) · Runaway Genome (Hero, +2%×√n hero damage) · Runaway
  Synchrony (Tower, +0.08%×√n damage per active tower) · Runaway Ossification
  (Infrastructure, +10×√n max Integrity) · Runaway Reflexes (Utility, +1.2%×√n hero speed).
- **Completion stays honest.** Section completion % and the hub Evolution ring count the
  CAPPED catalog only (`hubProgress` filters `infinite`); Runaway levels surface separately
  (section `endlessLevels`, the ∞ chips, and the "Runaway Levels" stat).
- Golden-safe: level 0 ⇒ no effect anywhere; save schema unchanged (levels live in the
  existing `save.upgrades` record).

**HQ screen overhaul** shipped with it: a **treasury banner** (current Genome Cores +
lifetime + total Runaway levels — the budget is finally on the screen that spends it), a
**sticky section jump rail** (chips with per-category completion, `scrollIntoView`), and the
Runaway card style (`is-runaway`: viral accent, ∞ badge, decade progress bar for rhythm
without a fake cap, cores-sunk readout, **hold-to-repeat buying** via `usePressRepeat`).

## §rebuild (2026-11, Batch G) — one-tap post-Molt rebuild

After every Molt the engine re-climbs: the G2 traces show 21–50 Genome levels re-bought BY HAND
each cycle. Once an account has Molted, the treasury band carries **⟳ Rebuild by Best Value**
whenever an unlocked, unmaxed upgrade is affordable:

- **Plan** — `genomeRebuildPlan(save)` (state/evolutionHQ.ts) spends the treasury greedily along
  the EXISTING Best Value ranking (bestPurchase's key: exact Power gained per Core, ties toward
  the cheaper level), re-ranked after EVERY level. Only `PowerParts.meta` reads `save.upgrades`
  — extracted as `meta.genomeUpgradeFactor` (accountPowerParts multiplies it in first, same
  evaluation order, so Power is byte-identical) — so each candidate is scored by swapping that
  one factor into ONE full parts computation: microseconds per score (the first version re-ran
  the full scorer per step and froze a phone for ~2.5 s on a 59-level plan). Its first pick is
  pinned to the Best Value strip's `bestAffordable`. Capped at `REBUILD.maxSteps` (120) per tap.
- **Confirm** — a dialog lists every upgrade (`L from → L to`, Cores), the total spend and
  `Power before → after`. The after-Power is scored on `genomeRebuildSave(save, steps)` — the
  SAME pure builder the apply uses, so the preview IS the outcome (pinned by evolutionHQ.test).
- **Apply** — `meta.applyGenomeRebuild(steps)` (guard `progress.rebuild`): re-validates every
  step against the live save (level, cost, gate, wallet) and refuses wholesale on any drift (the
  dialog re-plans); otherwise ONE persist, the same Account XP per level as `buyUpgrade`, one
  Power announcement, and a one-line summary under the treasury.
