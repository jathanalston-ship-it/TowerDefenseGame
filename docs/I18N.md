# Localization — typed t() layer (EN / ES / PT)

The i18n core is `src/i18n/index.ts` — zero dependencies, ~230 lines, fully typed.

## Architecture

- **English is the source of truth.** The `EN` catalog is a `const` object literal; its keys
  define `MsgKey`. Every other locale is declared `Record<MsgKey, string>`, so a **missing or
  extra translation is a compile error** — the suite never has to police key sync.
- **`t(key, vars?)`** returns the current-locale string, interpolating `{var}` slots
  (`t('liveops.weekendIn', { days: 3 })` → `Weekend Surge in 3d`).
- **Locale store**: `getLocale()` / `setLocale()` persist to `localStorage`
  (`assimilate.locale`) and notify subscribers; components call **`useLocale()`**
  (a `useSyncExternalStore` hook) so a locale switch re-renders them live — no reload.
  First boot auto-detects from `navigator.language`, falling back to English.
- **Picker**: Settings → Preferences → Language (`Hub.tsx` SettingsScreen).

## Migration convention (the beachhead)

- **All NEW user-facing chrome strings go through `t()`.** Add the key to `EN`, then the
  compiler forces the ES/PT rows before anything builds.
- **Migrated so far**: hub navigation (groups + items), Settings panel, Commander
  designation prompt, service-worker update toast, LiveOps strip chrome.
- **Content strings stay English for now** (tower/card/enemy names, help wiki, event
  names…). The registries can grow optional `nameKey` columns later without touching the
  core; the systemRegistry `localization: 'inline-en'` field marks each system still
  holding inline strings.
- A component that renders `t()` output **must call `useLocale()`** (once, top of the
  component) or it won't re-render on switch.
- Keep markup out of catalogs. For rich text around a slot, split on the literal slot in
  JSX (see `CommanderName.tsx`'s bolded `{name}`).

## Tests

`src/i18n/i18n.test.ts` — every locale covers every key non-empty, `{slot}` sets match EN
in every locale, interpolation, and live locale switching. Key *presence* is compile-time.

## Adding a locale

1. Add the code to `LOCALES` (e.g. `'de'`).
2. Declare `const DE: Record<MsgKey, string> = { … }` — the compiler lists every key.
3. Add it to `CATALOGS` and to the Settings picker's label ternary.
