# WEBSITE.md — the public site: architecture, patch notes, ads & analytics

Everything outside the game itself. Deployment mechanics: docs/DEPLOYMENT.md. Launch
manual: docs/RELEASE-GUIDE.md. Patch-note pipeline internals: docs/CHANGELOG-PIPELINE.md.

## §architecture — a GENERATED, committed static site at the domain root

The marketing site is generated by `npm run site` (`scripts/gen-notes.ts` refreshes the
patch-note data, then `scripts/gen-site.ts` renders the `site/*.ts` templates) into
plain HTML committed under `public/` — Cloudflare Pages serves it directly, the dev
server previews it, every diff is reviewable, and the drift test keeps the committed
output in sync with the generator. **Never hand-edit generated pages; edit `site/*.ts`
and re-run `npm run site`.**

- **Home is the domain root** (`public/index.html`); the full site lives beside it:
  `/about/ /features/ /roadmap/ /guides/** /encyclopedia/** /blog/** /news/ /faq/
  /leaderboards/ /contact/ /credits/ /privacy/ /terms/ /cookies/`, plus `404.html` and
  a generated `sitemap.xml`.
- **The GAME is its own Vite entry** (`play/index.html` → `dist/play/`) served at
  `/play/`. PWA `start_url`, the SW shell precache, replay-share links and Stripe
  return URLs all point at `/play`.
- **Routing** (`public/_redirects`): no root redirect and no SPA catch-all — Home and
  `/play/` are real assets, unknown paths hit `404.html`. One legacy rule maps the
  retired `/welcome/*` URLs to Home. `public/site.js` forwards legacy game deep links
  (`?replay/?daily/?checkout/?session_id=` on `/`) and standalone-PWA visits to
  `/play/`.
- Media (staged Hi-DPI screenshots, the frame-stepped trailer) lives in
  `public/media/` — re-shoot after big visual updates (recipe: docs/AI_HANDOFF.md).

## §patch-notes — ONE pipeline feeds the site AND the game

`npm run notes` (Chronicle — docs/CHANGELOG-PIPELINE.md) classifies git history into
categorized, quality-controlled releases in `changelog/ledger.json` and writes both:

- `site/patchnotes.json` → rendered by `npm run site` into **/news/** (client-side
  search over pre-rendered entries) and the Home "latest patch" card.
- `src/changelog/releases.gen.ts` → the in-game **Update Briefing**
  (per-player "what's new since you last played", save `patchNotes.seen`).

Dev-blog DRAFTS (`docs/devlog/DRAFT-*.md`, plus `npm run blog:draft`) publish as posts
in `site/blog.ts` after a human pass — never automatically.

## §ads — display ads on the SITE only, never in gameplay

- Every placement is a labelled `.ad-slot[data-ad-slot]` container; `public/site.js`
  is the single mount point. With `AD_PROVIDER = 'none'` (launch default) slots stay
  hidden — no empty boxes, no layout shift, no third-party requests.
- `npm run set-ads -- google --client ca-pub-…` flips the stack on (CSP hosts,
  ads.txt, site provider stamp); `-- off` restores the launch state. AdSense unit ids
  map per-slot in site.js once created in the dashboard.
- The GAME shows no display ads anywhere; menus carry only the opt-in Field Research
  lane (docs/RESEARCH.md). No interstitials, ever, by design.

## §branding / PWA

- `public/manifest.json` — installable identity (standalone, portrait, `start_url`
  `/play`); icons derive from `favicon.svg` (192/512/maskable/apple-touch);
  `public/og.png` (1200×630) is the social card.
- The game ships a versioned offline service worker (`public/sw.js`, stamped per
  build — docs/DEPLOYMENT.md §sw) precaching the `/play/` shell.

## §analytics

1. **Cloudflare Web Analytics** (no cookies) — enable per docs/DEPLOYMENT.md; the CSP
   already allowlists the beacon.
2. **Aggregate game counters** (`/api/events` → D1): per-UTC-day `(kind, count)` rows,
   no identifiers; batched fail-soft client (`src/net/events.ts`), kinds allowlisted
   server-side.
3. **Server-truth purchase counters** (webhook/claim) — conversion measured from money
   events the client can't fake.

Store funnel: `store_open → checkout_start → purchase_paid → purchase_fulfilled`;
read with SQL over D1 (`npx wrangler d1 execute assimilate-db --remote --command …`).

## §testing

`site/gen.test.ts` — the website contract: every page carries full SEO fields
(title/description/canonical/OG/JSON-LD), every internal link resolves, the sitemap is
complete, no placeholder copy survives, and the committed `public/` output cannot
drift from the generator. Runs with `npm test`.
